# Проверка Multiplayer 0.1.16.0 — DVSeasons 0.3.25

Дополнение 0.3.27: игровая проверка выявила пропущенный в исходной модели API случай — MP создаёт новый ServerPlayerWrapper на каждый внешний пакет. Прежняя коллекция объектов игроков не узнавала отправителя команды отопителя. Теперь регистрация, готовность и отключение используют PlayerId; рассылка получает актуального игрока через Server.GetPlayer. Тестовая граница воспроизводит новые обёртки на каждом запросе. Для исправления отопителей обновить нужно хоста и клиентов до 0.3.27. Подробнее: [релиз 0.3.27](RELEASE_0.3.27.md).

Проверена установленная версия MP и её API, обработчики сервера/клиента, загрузка мира и сетевые пакеты. В исходном журнале DVSeasons 0.3.24 регистрировал оба обработчика с протоколом 7; подтверждения входа удалённого клиента в этом журнале нет.

## Обнаруженные проблемы и исправления

1. Хост заново инициализировал снег при ручном выборе сезона, клиент этого события не получал. Протокол 8 передаёт ревизию выбора: повторный выбор того же сезона также работает, периодические пакеты не повторяют сброс. Сброс применяется после готовности мира.
2. Передавался сезонный SnowAmount, но не фактическая сохранённая плотность динамического покрова. Теперь клиенты получают и её. Локальные настройки отключения снега сохраняют силу.
3. Хост мог изменить отопитель после раннего запроса клиента, пока клиент ещё грузился. В PlayerReady теперь повторяется снимок отопителей для клиентов, согласовавших протокол. Отключённые игроки удаляются из рассылки; подписки сервера снимаются при остановке и Dispose.
4. MP 0.1.16 пропускает оригинальные SimComponent.Tick на клиентах. Дополнительные Harmony prefix/postfix не должны параллельно менять реплицированные данные. SeasonalThermalController теперь запускает сезонную физику только при локальном авторитете; клиент сохраняет лишь исправление отображения температурных ламп.
5. При повторном подключении/включении сбрасываются счётчик принятых пакетов и задержка запроса. Отключённый/удалённый мост не обрабатывает старые пакеты. Статус «синхронизировано» появляется после первого корректного состояния.

## Что передаётся

| Состояние | Источник и передача |
| --- | --- |
| Фаза сезона, переход, температура воздуха | Хост; снимок примерно раз в секунду и немедленно при ручном изменении |
| Длительность сезона и выбранного перехода, режим перехода | Хост |
| Интенсивность осадков, ветер, освещённость снега | Хост |
| Общая плотность динамического снега | Хост, включая восстановленное сохранение |
| Отопители конкретных локомотивов | Клиент запрашивает изменение только для занимаемого локомотива; хост подтверждает и рассылает |
| Температуры/запуск/аккумуляторы/тормоза | Дополнительная физика мода выполняется на хосте; штатная сеть MP отвечает за репликацию игры |

## Ограничения

История прогрева кабины, степень таяния снега на каждом локомотиве, маски проталин/дворников/наледи и следы на рельсах не передаются этим протоколом. Они вычисляются локально по погоде, отопителям и состоянию составов. После позднего подключения их вид может временно различаться. Отдельные снежинки, листья, бабочки и пчёлы также локальны; совпадение каждой частицы не проверяется и не обеспечивается. Графические настройки игроков могут отличаться.

Все участники должны обновить DVSeasons до 0.3.25. Протокол 7 несовместим с 8; старый входящий пакет отклоняется до чтения новых полей, без исключения выхода за конец потока.

## Проверки

- 200 xUnit-тестов: производственные SeasonRuntime, MultiplayerSeasonBridge и сериализаторы с заменёнными границами Unity/MP API. Сценарии хоста с двумя клиентами, ранний запрос/поздняя готовность, отопитель, чужой локомотив, повторные и устаревшие пакеты, переподключение, отключение мода, подписки сервера, ручной повтор сезона и сохранение локального календаря.
- Сборка против установленного MultiplayerAPI.dll, без ошибок и предупреждений.
- Unity 2019.4.40f1 с DLL игры: загрузка сетевого адаптера, включение/снятие сезонных физических патчей при смене роли, восстановление покрова клиента, регрессии трёх дизельных стартеров и BE2. Маркер `MP_016_COMPATIBILITY_OK` в локальном `artifacts/verification/mp-0.1.16-unity.log`.

Тесты не создают настоящую сетевую сессию на двух компьютерах. Для окончательной игровой проверки нужны одинаковые версии у участников и контроль входа в уже заснеженный мир, переключения сезонов, отопителя, холодного запуска с клиентского места и повторного подключения.
